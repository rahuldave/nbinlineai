# Example notebook audit

This audit reads every cell, saved output, and AI question in all **25 existing notebooks**: 24 gallery notebooks and `data/ecosystem-lesson.ipynb`. The source reviewed is main commit `85f91d9b6a51c000adc8360e77e584f122911244`. None was executed for this audit, and all existing notebooks are retained. Saved evidence describes earlier runs; it does not establish that a fresh run will succeed with your devices, browser, network, or model connection.

The examples are sensible as individual tool lessons. They are less effective as application tutorials because a reader must join the steps, handle pending receipts, and decide what to produce. The five new [application notebooks](examples.md#complete-applications) fill that gap. Their outputs and AI answers are deliberately empty, ready for your own run.

## What to carry into your own application

1. **Check the final effect.** A requested save, initial receipt, confirmed attachment, inserted code draft, and completed AI question are different outcomes. The existing traces make many of these visible, but a demonstration that stops early needs your next step.
2. **Use values and references deliberately.** Ordinary tools return values. Direct browser tools return a mutable receipt that can later contain real Python values. AI browser tools return snapshots and descriptors. The [application guide](tool-applications.md) and [receipt tutorial](https://rahuldave.com/nbinlineai/notebooks/application-receipts-to-values.html) show how to continue into Python.
3. **Keep paths honest.** A browser-saved path is relative to the Jupyter server root. The kernel's working directory can differ. Foundation, playback, and attachment need their documented filename-reference layout; file checks in other media examples also use a root assumption. Do not turn a returned path into `Path.cwd() / path` without an explicit root mapping. The new media applications use in-memory capture and owned Python exports, or request that mapping for saved-file handoffs.
4. **Do not infer senses from descriptors.** The model cannot hear a recording or see a screenshot merely because a tool reports its MIME type and hash. Only a still explicitly attached to the question becomes image input. Transcription, video understanding, and media mixing require additional processing.
5. **Finish with something useful.** The new presenter, bug-report, data-investigation, and project-handoff notebooks preserve local artifacts rather than stopping at a tool receipt. They separate interactive stages and keep cleanup from deleting those deliverables.

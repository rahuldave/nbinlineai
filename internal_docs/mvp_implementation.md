# API prompt-cell MVP implementation and verification

**Historical implementation log through 0.1.5.** For current 0.1.7 behavior and test commands, read [the developer handoff](developer_handoff.md), [context model](cell_kernel_model_and_context_selection.md), [tools/protocol](bundled_tools.md), and [release verification](releasing.md). The early context budgets and scope in this log are not current defaults.

The JupyterLab extension stores AI prompts and their paired markdown answers in notebook cells with `metadata.nbinlineai`. The frontend selects preceding cells, sends one authenticated prompt request to the Jupyter Server, reads streamed SSE events, and renders the answer in the paired cell. A rerun updates that cell. Only AI prompt cells intercept Shift+Enter; ordinary code cells continue through JupyterLab.

The server resolves the notebook session to its Python kernel. It presents bounded code and ordinary Markdown source above the prompt, plus earlier completed AI turns, to FastLLM in notebook order. It substitutes `$` references from the live kernel namespace and exposes only explicitly named `&` functions as tools. Tool calls are checked against the run's allowlist and executed in that same kernel with JSON arguments. OpenAI and Anthropic API keys stay outside notebooks: users can save them through Configure AI in an XDG-compatible per-user file, or set server environment variables. The browser receives provider availability, key source, and model defaults, never credential values. A cancelled run can stop subsequent work but cannot reverse a function side effect already performed.

## Version 0.1.4 verification before release

Notebook metadata now holds one set of AI defaults for provider, model, response style, and reasoning effort. The first AI insert snapshots effective defaults without writing AI metadata when an ordinary notebook opens. Prompt cells inherit those defaults until a cell override is chosen; clearing the override restores inheritance. The Configure AI dialog allows edits to each style's instructions, with Reset to the server default and Retry after an unconfirmed settings write. The server validates effort against its model catalog and accepts custom instructions for one run's selected style. Keep answer protects a completed nonempty response by default: Run is disabled and Shift+Enter advances without another request until the checkbox is cleared.

## Version 0.1.5 verification before release

The notebook defaults row now has a Keep AI answers setting, enabled by default. A prompt cell inherits it unless its own Keep answer checkbox is changed; **Use notebook setting** removes that cell override. JupyterLab's native Run All executes mixed code and AI cells in notebook order through a queued cell executor. Completed protected answers skip provider requests, while eligible prompts run. Errors and cancellation stop later cells in that run; a later Run All starts fresh. Edited answer Markdown is used as the earlier answer in subsequent AI history.

## Current scope

The MVP handles text prompts and bounded text tool results in Python notebooks. It does not send rich outputs or images as context and does not implement ChatGPT subscription sign-in. The subscription architecture remains in [the FastLLM and ChatGPT design](fastllm_and_chatgpt_subscription.md).

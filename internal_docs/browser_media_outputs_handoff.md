# Notebook output/view/canvas implementation handoff

**Source topic:** `codex/browser-media-outputs`, based on reviewed foundation `c876fd4c77517c08b60670a0ecc66029872b02b3`. This topic adds the ten Group 3 browser operations; it depends on the shared recorder interface from `0797c45d5f5d5fc932940c1a60bfa3308574690f` and, for final public recording/cleanup, the full capture family. This is implementation-specific source behavior, not PyPI 0.1.15 behavior.

`nbinlineai/browser_output_tools.py` contains nonblocking Python wrappers, registered through `nbinlineai.tools`. `frontend_bridge.normalize_action` bounds model calls. `src/browserNotebookOutputs.ts` owns a per-`BrowserOperationContext` ledger keyed by actual `IOutputModel` objects rather than indices. Its listeners on `changed`, `streamText.changed`, `outputs.changed`, and notebook cell-list changes invalidate refs and dependent canvas sources. No output renderer is created by listing or exporting. `src/browserMediaResultBudget.ts` conservatively counts Python `json.dumps` ASCII escapes and separators under the foundation's 1,500-character operation-result admission, with a 1,400-character family target. Output, view, selection, and canvas pages use that bound; Unicode text pages preserve complete codepoints and `next_start` uses JavaScript string positions. Structured `read_output` preflights traversal size before stringifying a table. Export uploads verified native bytes through the foundation's authenticated binary route. SVG is uploaded from the original MIME data, not serialized from sanitized DOM. Supported existing text/Markdown/JSON/data-resource MIME is encoded as UTF-8 bytes; the Python receipt keeps bytes and actual MIME. A saved data resource uses a `.json` suffix.

`src/browserNotebookViews.ts` reads the origin panel only. `src/browserNotebookCanvas.ts` accepts one stock, materialized `text/html` output renderer and scopes its DOM lookup to that output widget. A ref binds the output, widget, and actual canvas node; output changes, renderer replacement, DOM removal, and owner disposal invalidate it. `captureStream` yields one video-only track registered in the common source registry. Its `onEnded` calls `recordingSourceEnded`; there is no second recorder. `src/browserNotebookRegion.ts` composes fully visible stock PNG/JPEG/SVG outputs and single-canvas HTML output by displayed rectangles, rejecting an entire request if any requested output is unsupported. It does not capture notebook inputs or use display sharing.

At integrated source head `e5ba74f2c38f0e66c6cc7aec9ac43916929b5367`, the exact copied `examples/browser-media-outputs.ipynb` runner exercised all ten output/view/canvas tools and the extra structured-data export; three focused output cases also passed. These four browser cases used disposable notebooks, deterministic pixels, a fresh frontend build/relink, isolated Chromium/JupyterLab on 8897, and real kernels. They covered unsaved/offscreen model discovery, same-byte replacement invalidation, native SVG and data-resource bytes, canvas node removal, region exclusions, and later Python receipts. No 8888 server was used. Final independent review, PR and CI status remain separate gates; this source behavior has not been released to PyPI.
